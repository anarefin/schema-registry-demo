Problem
Contracts own topology (ADR-0002) but TypeMapping stays hand-duplicated in both services — half a plug-in module.

Solution
Deepen contracts (or a thin wiring jar above the enforcer ban) so TypeMapping beans auto-register with topology; delete the four service config classes.

  • locality at event boundary
  • leverage: one interface, N services
  • delete 4 shallow adapters
Contradicts spec Principle 3 / ADR-0002 (“schema-resolution wiring untouched”) — worth reopening: topology migration left the costliest seam behind. core ↛ contracts still holds via neutral leaf or contracts→core types only.

Problem

Solution
Tiny messaging-conventions leaf that core, kit, and optionally gen-tools depend on — dependency inversion, not core→kit.

  • locality of naming rules
  • leverage across banned seams
  • one adapter per consumer module
SchemaFileNaming dual copy is explicit in ADR-0004 — reopen only if a third consumer appears or parity tests fail. Retry-tier duplication is not ADR-blessed and is cleaner to fix first.

Top recommendation

Contracts-owned TypeMapping auto-configuration

Highest leverage. Matches post-ADR-0002 reality (contracts already self-activate for topology). Biggest locality win for the POC’s extension cost. Candidate 3 is the best core-only follow-up if Principle 3 stays closed.
